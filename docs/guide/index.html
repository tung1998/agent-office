Your own AI office,
running on your machine.

agent-office gives every project a team of AI agents. They take work over chat (dashboard, Discord, Telegram), edit code in isolated git worktrees, run your dev servers, watch your services, and ask you only when something needs approval.

1What is agent-office

Think of it as an office where the staff are AI agents and you are the manager.

👥 A team per projectLead, developers, QA, reviewer… picked from the library, or by AI from the repo.
🌳 Isolated editsEach chat works in its own git worktree. You see a diff before anything reaches your repo.
🔐 Permission per actionRead, edit, run a command, restart a container, commit, push: each one allowed, asked or blocked.
⏰ Always onSchedules, webhooks, chat bots, monitors and Burn keep work moving while you sleep.
🔌 One gateway outMCP servers, bots and logins live in the office, with one permission model and one log.
💸 Cost-awareEvery AI call is logged with its cost. Budgets and fallback connections keep you in control.

Key words

2Install & first run

You need git and at least one AI account. scripts/install.sh checks for Go ≥ 1.27, Node 22 and pnpm and installs whatever is missing (into ~/.local, no sudo). Runs on macOS and Linux; on Windows run powershell -ExecutionPolicy Bypass -File scripts\install.ps1: it installs WSL2 + Ubuntu when missing (the first run needs administrator and maybe a restart, then run it again) and builds inside Ubuntu.

The AI way 🤖It's an office run by AI, so let an AI set it up. Clone the repo, run claude (or codex) in the folder and say "run this project". It builds everything, starts the office and hands you the link. If it asks you something, that's your first approval request.

Or by hand:

scripts/install.sh                # checks/installs Go, Node, pnpm; builds the server and the dashboard
./bin/office run                  # API on :8787, dashboard on http://localhost:2704
  1. Open http://localhost:2704 (or the server's address) and sign in with admin / admin.
  2. Set your own email and password. The default account can do nothing else until you do.
  3. Follow the checklist on Overview → Machine: AI connection → project → agents.
  4. Optional: ./bin/office service install --now starts the office every time you log in (LaunchAgent on macOS, systemd user unit on Linux).
Skip admin / admin?office init asks for the admin email and password (Enter keeps admin / admin). In Docker or a script, office user create --email you@example.com takes the place of admin / admin. Forgot a password? office user passwd --email ….
Where is my data?By default in ~/.agent-office (one office for the whole machine). Run office init --local inside a repo to keep data in <repo>/.office instead.
Remote accessReach the dashboard from your phone or laptop over Tailscale or LAN. MCP OAuth logins still work: paste the link your browser lands on after signing in.

3Overview

Your inbox. Everything that needs a decision, from every project, in one list.

  • Work tab: proposals waiting for approval, failed jobs, stopped processes, monitors that are down, disabled automations, disconnected bots, and unread chats. Act in place, or Skip all.
  • Performance tab: cost and runs per day, per project and per model, over 7/30/90 days.
  • Machine tab (admin): CPU/RAM, the office's own processes (close or kill), AI connections and the setup checklist.

Bell and notifications

  • The bell in the header counts what needs you. Click it for the list, each item with its buttons right there: Approve / Skip (a card waiting), Mark seen (a chat answered), Continue (a chat stopped for tokens), Hide, and Open.
  • Something new shows a toast in the top corner with the same buttons; a card to approve stays until you decide it.
  • Press Turn on browser notifications in the list to get notifications with Approve / Skip even from another tab (at least one dashboard tab must be open; Safari shows no buttons). On macOS, set Chrome's notification style to Alerts to see the buttons.
Live updatesThe dashboard keeps one server-sent-events connection open. New messages, job results and status changes appear without refreshing.

4AI connections

Tell the office which AI accounts it may use. Agents pick from these.

KindNotes
Claude Code CLIUses your Claude subscription. Install and log in from the dashboard. Shows usage limits (5-hour and weekly windows).
Codex CLIUses your ChatGPT/Codex account. Same install and login flow.
Anthropic / OpenAI APIAPI key, stored encrypted. Cost is computed from the price table (editable).
OpenAI-compatible18+ presets: OpenRouter, Gemini, DeepSeek, GLM, Kimi, Ollama… or any base URL.
  1. Click Add connection, choose a kind, and paste a key or log in.
  2. Click Test (free) or Send a test prompt (uses tokens).
  3. Mark one as default. Agents without their own choice use it.
Fallback connectionsOn each agent's Model card, add backup connections in order. If the main one fails or hits its limit before doing anything, the turn moves to the next one and says so in the chat ("A failed, switching to B"). A connection that is out of quota goes to the end of the list.
Limits alertWhen a CLI connection gets close to its usage limit, the office can post a warning in a bot chat you choose.

5Projects

Every piece of work happens inside a project.

  1. Folder: pick an existing folder with the folder tree.
  2. Clone: paste a git URL (https, ssh or scp style). The office clones it next to its own folder by default.
  3. No folder: a helper for planning, writing or anything machine-wide.
  4. A new project starts with the Assistant agent so it can chat at once, then opens Set up with AI to pick more from the library (run it again any time from the Info tab).

Inside a project the tabs are: Chat, Automations, Operations, Agents, Permissions, and for admins also Files, Skills, MCP, Burn, Change log, Info. The header shows the git branch with fetch, commit and push buttons.

6Set up with AI

Let AI read the repo and pick what the project needs from the library.

  1. Scan (free): manifests, frameworks, infra files, existing agent files such as CLAUDE.md or .claude/agents.
  2. Propose: the AI picks agents, workflows, automations, skills and MCP servers from the library, with a reason for each; agents come with the project's own context.
  3. Untick anything, or click Edit (name, permission, context), before Apply setup. It only adds: current agents stay as they are, and automations are created paused so you check their schedule or webhook first.

7Agents from the library

A project's agents come from the library, adjusted to fit; how they work together is a workflow.

Team shapeLibrary agentsGood for
One agentAssistant.Small repos, personal helpers.
TeamA team lead coordinating specialists: frontend, backend, QA, review, DevOps… with the Handoff, Feature and Review PR workflows.Most code projects.
CouncilPlanner, Executor and Auditor with the 3-party council workflow: proposals are voted on, can be vetoed, and the result is checked.Risky changes, payments, security.

Add agent opens the library: pick one, adjust its name, role and model tier, then add it; its instructions and permissions are edited on its own page. There is no whole-team swap any more: add, edit or remove agents one by one (History can still restore).

Fix until it passesA task loops (edit → build/test → fix) until checks pass. It stops when it can't make progress, needs your answer, or runs out of budget.

8Agents

Each agent is a staff member you can tune.

  • Stats: runs, cost and error rate per day and per model, recent chats.
  • Model: AI connection, model tier (strong / balanced / fast), thinking effort, fallback connections.
  • Instructions: role and extra rules, added to the system prompt.
  • Permissions: a preset (read-only, edit, operate, admin…) or individual permissions. See Permissions.
  • Memory: long-term notes the agent carries into every chat ("repo uses pnpm", "work on main"). Agents can add notes themselves with remember. Long notes get compacted by a fast model.
  • History: every settings change with a diff. Restore any version.
  • On/off switch: a paused agent is hidden from chat and @. Anything that calls it gets a notice instead of spending tokens.

Every card saves itself as you edit.

9Chat

Where the work happens. Talk to one agent or pull several into a group.

Sending work

  • Type a task and press Enter. Answers stream in, with every tool call (read, edit, command) shown inline.
  • @name pulls another agent into the chat. Each agent has its own session and sees only new messages.
  • /skill runs a skill from the project, the machine or a plugin.
  • Attach images, PDFs, text files or logs (drag, paste, or the paperclip).
  • Agents can delegate: work runs in the background like a sub-agent, and the result comes back into the chat.

Handing work to another project

  • In Permissions → Linked projects, pick the projects this project's agents may hand work to (one way).
  • Say "have the admin project build the … page": the agent opens a chat there in your name with the full request. The agent there works in its own repo, with that project's permissions.
  • When it answers, the answer comes back to your chat as a Report from … card with its text folded. Your agent answers what it can on its own and asks you what needs your call. Follow-ups go into the same chat over there.
  • Cards waiting over there show right in your chat, to approve on the spot. Sending without asking needs the Send to linked projects permission.

Organising chats

  • Tags: add from the tag row or the ⋯ menu. Filter by several tags at once.
  • Source filter: web, Discord, Telegram, automation, Burn.
  • Copy link to any message. Paste a chat link into another chat and the agent reads it.
  • Agents can search past chats (search_history) when you say "like last time".
Edit modesWorktree (default): the agent edits a private copy and you approve the diff. Direct: edits the project folder like the CLI does. Set per chat, per automation, or per project.

10Approvals

Agents propose. You decide.

CardWhat it does when approved
DiffMerges the agent's worktree changes into the project. View per file, side by side.
CommandRuns a command that isn't on the agent's allow-list.
Process / containerStart, restart or stop a dev server, job or docker compose service.
GitCommit, create a branch, push (push always needs a person).
Settings changeAn automation, agent, monitor or policy the agent wants to create or edit.
MCP callA tool that writes on an external service.
  • Approve: it runs, and the agent continues on its own.
  • Approve & always allow: saves the command pattern to the agent's permissions. Dangerous patterns are refused.
  • Reject: the agent is told and can try another way.
  • Skip: dismiss without the agent running again. Skip all clears a project.

In order. A card can only be approved once the cards before it are decided; the agent continues only when every card of the chat is decided. This holds on the dashboard, in bots (/approve all stops at the first card out of turn) and for diffs merged automatically. A card from an older answer asks you to confirm, and a very large diff (over 100 files or 1 MB, usually a whole branch copied by mistake) shows a red warning before it is merged.

Approve from anywhereFrom the header bell, a toast or a browser notification (see Overview). Cards also appear in Discord/Telegram with buttons, or use /skip. Deciding in one place updates the other.

11Permissions

Per action, per agent, with presets so you don't start from zero.

  • Command packs: commands grouped by tool (Git, Go, Docker…), with read-only packs. Edit them or build your own.
  • Command patterns: go test *, pnpm typecheck… A trailing * allows any arguments, but dangerous flags (-exec, --output, --no-index, paths outside the project) are still blocked.
  • Protected files: secrets and files agents may never edit.
  • Linked projects: projects whose chats the agents may open, send work to and read (see Chat → Handing work to another project).
  • Administrator is set on the agent. Automations inherit it or override it.

12Operations & monitors

Run your project like pm2, and let the agents read the same logs you do.

Processes

  1. Click Scan: the office finds commands in Makefile, package.json, docker-compose.yml… Pin the ones you use.
  2. Start, stop or restart. Services can auto-restart on crash and auto-start with the office.
  3. Open the live log. Ask agent attaches the last 300 lines to a chat; Fix starts a new chat and sends it right away.

Containers

Docker compose stacks: status, ports, CPU/RAM/network, up/stop/restart/down/pull/build per stack or service, live logs.

Monitoring

Each process and each compose service can be monitored: tap the ♥ on its row to turn it on. Its badge shows the 24h uptime; open it for Up/Down events, check now, and AI analysis when Down (an agent investigates, with a daily budget and a cooldown).

13Automations

Work that starts on its own: on a schedule, from a webhook, or from a chat message.

TriggerExample
ScheduleCron + timezone, or every N minutes. "Mon–Fri 08:00: brief me on yesterday's commits."
WebhookA secret URL with a token. "Sentry alert → triage and propose a fix."
Telegram / DiscordA message in a bot chat, optionally a command like /deploy.
ActionCost
Script (bash, node, python)Free. Runs in the project folder, gets the payload on stdin and $OFFICE_PAYLOAD. Uses no AI. A line @@quest … gives Burn a quest; a line @@workflow <key> <input> opens a workflow (code, wait, condition, an agent only where needed).
ChatSends a prompt to an agent. Use {{payload}}, {{today}}.
Guard railsMax runs per hour, daily cost, debounce (collapse bursts of webhooks), parallel runs, max minutes per run, and auto-disable after N failures. Agents can propose automations too, and they always wait for your approval.

14Discord & Telegram bots

Give work to your team and approve proposals from your phone.

  1. Create a bot in Discord (Developer Portal) or Telegram (@BotFather) and paste its token.
  2. Add Admins and Users by their chat IDs. Only they can talk to it.
  3. Talk to it: "@bot fix the failing test", or send it a direct message (no tag needed). Discord threads keep each task separate. The bot shows when it's working, posts images and files, and sends approval cards with buttons.
  4. In the office chat, a message from a bot has a sender line above it: display name, @username, direct message or server/group, and a link to the original. An id linked to an account (see Users) shows that account's name.
  5. Add commands: each command is its own automation (script or chat).

15Burn

An agent that keeps working on a project by itself until a time you set.

  • It finds three kinds of work: unfinished work (TODO/FIXME, failing tests, stale proposals), improvements, and small bugs.
  • Each item runs in its own worktree. Results go to a local branch or a diff waiting for approval.
  • On is on: a switch at the top of the tab, nothing more is asked. Each time it turns on, Burn runs by its saved Schedule: until the AI connection's weekly limit resets (the default; 8 hours if it cannot be read), for N hours, until a set time (e.g. 7:00), or until turned off.
  • Turn on by schedule: pick days of the week and a time (e.g. Mon–Fri at 22:00). At that time Burn turns on if it is off (up to an hour late if office just started); turned off by hand, it waits for the next time. The tab shows when it turns on next.
  • Settings are in one place, in blocks: Schedule; What to work on (template, order, focus "checkout first, skip docs"); Who works (lead agent, model tier, pieces at once 1–5); Checks & reports (check commands, review, the bot that gets the summary); Advanced.
  • Build a project from an idea: Projects → Add → From an idea (idea, optional stack, folder). Office creates an empty repo and a Burn on the Build a project template (not started). Start it: the first piece sets things up (SPEC.md, features.json with an acceptance command per feature, AGENTS.md, PROGRESS.md, a scaffold whose build/test pass). Then the Burn does one feature at a time, in order; every check re-runs the acceptance of all finished features. Set the Burn's checks from AGENTS.md and a review cap.
  • Turning it off finishes the current item, then it stops (Stop now pauses it; turned on again, it resumes). Its chat appears in Chat with a 🔥, where you can steer it.
Admin onlyBurn runs with full machine access and no per-step approval, and it uses a lot of your AI quota (the ⓘ next to the switch spells this out).

16Files

Browse and edit the project without leaving the dashboard (admin).

  • Gitignored and secret files are hidden by default. Show hidden reveals them.
  • Saving a secret or protected file asks for confirmation. If someone else changed the file meanwhile, you get a conflict instead of overwriting.

17Skills, MCP & library

Everything the agents can use, in one place.

Skills

See every skill on the machine, install into a project, save to the library, or write a new one with an AI helper (Write skill). Skills are checked for unsafe content before installing.

MCP gateway

  1. Add an MCP server (HTTP or stdio), or Move into office one you already have in Claude Code.
  2. Servers that need a login: click Connect. The office handles OAuth (discovery, client registration, PKCE, token refresh).
  3. Assign servers to agents and set a permission per tool: allowed, ask, or blocked. Tools that write ask by default.
  4. Every call is logged. Claude Code, Codex and API agents all go through the same gateway.

API agents, Codex and Gemini CLI discover tools when needed with find_tool, then invoke them with call_tool. A short initial hint names assigned and unassigned servers; search returns at most 5 schemas per page. An empty query lists servers, access and catalog status; unassigned servers expose no schemas and cannot be called. The catalog uses the last check and identifies unchecked, empty or stale catalogs; check the server again in office when needed. Search ignores Vietnamese accents but does not translate: agents use English keywords for English descriptions, or retry with the server name. MCP results for Codex/Gemini preserve images and resources; API results currently remain text. Claude Code keeps its direct connections without duplicate toolbox tools. Antigravity does not currently receive MCP configuration from office.

18Office assistant

A chat that manages the office itself, across all projects.

Pick a project scope with the chip, and the assistant can read and propose changes to any setting: connections, budgets, agents, automations. Changes come as cards you approve. You can also give it fallback connections.

19Watch

Your own dashboards: a grid of boxes, each showing a chat, a console, a figure or a list, from any project.

  • Several dashboards as tabs, each with a name, a refresh interval and a default project.
  • A 12-column grid like a phone's home screen: drag a box by its grip, resize it by its corner; the others make room. Narrow screens get a packed copy (8 or 4 columns).
  • 20 widgets in Add box: chat, process and container (console, controls, CPU/RAM), several consoles, monitor, figure, jobs, chart, incidents, approvals, machine, AI budget, AI limits, cost breakdown, status lights, git, controls, automations, web page preview, note. Each box has its own settings (⚙).

Boards are kept in this browser. Consoles share the tab's one event stream, so a board full of logs does not use up the browser's connections.

20Jobs

Every run, from every project: chat turns, automations, monitor analyses.

Cancel a running job or retry a failed one. Jobs cut off by a restart are marked failed, never silently re-run.

22Project info & budgets

Budgets exist at three levels: the whole office (AI connections page), each project (Info tab) and each automation. A run that would go over is blocked and reported on the Overview.

23Users & account

  • Admin: everything. Member: chat and use projects, delete only their own chats.
  • Personal tokens let other tools reach the office's MCP endpoint with your role's rights. They expire after 30/90/365 days, or never.
  • Link Discord / Telegram (an account's ⋯ menu): enter the numeric user ID. Messages to a bot from that id show the account's name, with "(you)" when it's yours. One id per account. It grants no bot rights (the bot's Admin list still decides), but the agent may send into other chats on that account's behalf.

25Updating office

The button appears only when the source differs from the running build. If the new build fails to start, the office rolls back to the previous one. The sidebar shows the version and last commit.

An office that upgrades itselfagent-office is a project like any other. Add its own folder as a project and ask its agents for what your work needs ("add a Zalo OA channel", "a monitor for SSL expiry"). They edit and test the source in a worktree, you approve the diff, then Update office rebuilds it. The office bends to how you work, one approved diff at a time.

27Tips & FAQ

Does it send my code anywhere?

Only to the AI connections you configure, exactly like using those tools directly. The office itself runs locally and stores data in SQLite.

Can agents break my repo?

In worktree mode they edit a separate copy. Nothing reaches your folder until you approve a diff. Commands outside the allow-list, git pushes and restarts all ask first.

How do I keep costs down?

  • Prefer script automations: they're free and call an agent only when needed.
  • Give simple agents the fast model tier, and set budgets per project and automation.
  • Add a cheap fallback connection so a limit doesn't stop work.

Recurring task?

Ask in chat: "every weekday at 8, check X". The agent proposes an automation, and you approve it.
